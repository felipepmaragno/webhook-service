# v0.12.0: Cryptography Protects Bytes, Not the Whole System

## Exact bytes are the contract

Signing a decoded JSON object is ambiguous because another implementation can serialize equivalent
JSON differently. Dispatch signs the exact body bytes sent on the wire and tells receivers to verify
before parsing. A fixed language-independent vector makes that contract testable outside Go.

The timestamp is part of the signed bytes. This lets receivers reject old requests without trusting
an unsigned freshness claim. It reduces replay exposure but cannot prevent legitimate retry or
redelivery, so event-ID deduplication remains a separate receiver responsibility.

## Rotation follows state ownership

Delivery rows freeze destination configuration so retries are deterministic. Secret rotation cannot
silently rewrite those rows without violating that model. The active subscription gets the new
secret for future delivery initialization, while existing deliveries retain the old one. This
creates an intentional overlap period at the receiver.

This is a broader engineering lesson: configuration rotation semantics must follow the durable unit
that owns in-flight work, not only the latest configuration row.

## API cleanliness is not data safety

The handlers were small and readable but returned domain subscriptions directly, making stored
secrets JSON-visible. A dedicated response DTO makes secret absence structural rather than dependent
on remembering to clear a field before encoding.

## Security claims stop at system boundaries

HMAC authenticates webhook request bytes. It does not authenticate API callers, encrypt PostgreSQL,
secure backups, prevent SSRF, terminate TLS, or create exactly-once delivery. The deployment contract
names those responsibilities explicitly so one implemented control is not mistaken for end-to-end
security.
