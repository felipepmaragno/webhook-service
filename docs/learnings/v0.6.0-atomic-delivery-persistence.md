# v0.6.0 — Atomic Delivery Persistence

## The failure window

The worker used to perform three independent actions:

1. deliver the webhook
2. write event state
3. write attempt history

Errors from the two database writes were logged, but not returned to the Kafka consumer.
The consumer then committed the batch. A transient database outage could therefore remove
the event from Kafka without creating its retry schedule in PostgreSQL.

## Why one transaction matters

Event state and attempt history describe the same delivery decision. If only one commits,
the system tells two incompatible stories. Grouping them in one transaction creates a useful
invariant: the outcome and its audit records either both exist or neither exists.

## Why this is still not exactly-once

PostgreSQL can roll back its own writes, but it cannot roll back an HTTP request that already
reached a webhook receiver. If the HTTP call succeeds and persistence then fails, Kafka must
redeliver to avoid event loss. That may call the receiver twice.

This is the correct at-least-once tradeoff:

- prefer a possible duplicate over silently losing the event
- expose a stable event ID so receivers can deduplicate
- commit Kafka offsets only after durable internal state exists

## Attempt-history limitation

An HTTP call followed by a database outage cannot be guaranteed to appear in attempt history,
because the history record is part of the failed transaction. After recovery, the repeated call
can be recorded. Also, attempt rows currently do not include `subscription_id`, so the schema
cannot uniquely identify one fan-out delivery attempt per destination.

That modeling improvement belongs in a separate increment; adding it here would mix schema
redesign with the persistence-safety fix.

## Engineering takeaway

At-least-once is an end-to-end contract, not merely a Kafka configuration. Every error between
the side effect and the offset commit must propagate through the call stack, and durable writes
that represent one decision should share a transaction boundary.
