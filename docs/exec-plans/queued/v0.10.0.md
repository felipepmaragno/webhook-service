# Execution Plan: v0.10.0 - Per-Subscription Delivery Persistence

> **Status:** Queued
> **Target:** Introduce stable event-destination delivery identity and destination-attributed attempts without changing runtime ownership yet.
> **Depends on:** v0.9.0 rate-control contract normalization
> **Followed by:** v0.11.0 delivery processing and retry cutover

## Goal

Create the durable model required for independent destination outcomes. Preserve current
runtime behavior during this increment so migration, repository, API, and compatibility
semantics can be validated before delivery and retry ownership moves.

## Accepted model

- An event targets a frozen set of active matching subscriptions when first initialized.
- A delivery is uniquely identified by event ID and subscription ID.
- Delivery state, attempts, next retry time, error, and retry lease belong to the delivery.
- Event status is a projection of its deliveries, not the retry ownership record.
- Historical aggregate attempts cannot be assigned to a subscription without evidence;
  migration preserves them as legacy event-level history.
- Events with no matching subscriptions remain valid and complete without a delivery row.

## Acceptance criteria

- [ ] New delivery identity and state are defined in domain and specification.
- [ ] Reversible migrations add delivery storage and destination attribution for new attempts.
- [ ] Repository operations initialize a frozen destination set idempotently.
- [ ] Delivery attempts reference the exact delivery/subscription.
- [ ] Event aggregate projection rules are deterministic for zero, one, and many deliveries.
- [ ] Existing aggregate rows and attempts remain readable without invented attribution.
- [ ] Current processing continues to use the old runtime path until v0.11.0.

## Phase 1: Contract and migration

### Step 1: Record the delivery identity decision

- [ ] Add an ADR defining frozen target sets, delivery identity, projection rules, and legacy compatibility.
- [ ] Define delivery states and allowed transitions independently of event state.
- [ ] Define behavior for deactivated/deleted subscriptions after target initialization.
- [ ] Define whether subscription URL and relevant policy are referenced or snapshotted; preserve enough information for deterministic retries.
- **Verify:** product, spec, ADR, and migration terminology agree.

### Step 2: Add schema

- [ ] Add a `deliveries` table keyed by stable delivery ID with a unique event/subscription pair.
- [ ] Store status, attempt count, retry schedule, last error, timestamps, and retry lease metadata on the delivery.
- [ ] Add delivery identity and subscription identity to new attempt rows.
- [ ] Add constraints and claim/query indexes justified by intended v0.11.0 access patterns.
- [ ] Keep legacy attempt attribution nullable and document why.
- **Verify:** migration up/down and schema constraint tests pass on empty and representative pre-v1 data.

## Phase 2: Domain and repositories

### Step 3: Add delivery domain model

- [ ] Add delivery identity, states, and transition helpers without reusing aggregate event methods.
- [ ] Define aggregate event projection as a pure, tested function.
- [ ] Cover mixed delivered, retrying, throttled, processing, and terminal states.
- **Verify:** domain tests prove state and projection invariants.

### Step 4: Add repository contracts

- [ ] Initialize an event and frozen delivery set idempotently in one transaction.
- [ ] Read deliveries by event and delivery ID.
- [ ] Persist delivery outcome with its attempts atomically.
- [ ] Add claim interfaces needed by v0.11.0, but do not activate them in the poller.
- [ ] Preserve legacy event and attempt reads.
- **Verify:** PostgreSQL Testcontainers tests cover duplicate initialization, rollback, attribution, and concurrent initialization.

## Phase 3: Read representation and compatibility

### Step 5: Expose delivery reads

- [ ] Add a read-only event-deliveries endpoint or representation without changing existing event/attempt responses incompatibly.
- [ ] Distinguish legacy aggregate attempts from attributed delivery attempts.
- [ ] Add pagination only if required to keep the endpoint bounded; record the chosen contract.
- **Verify:** API tests cover zero, one, many, and legacy deliveries.

### Step 6: Document cutover boundary

- [ ] Update architecture and package READMEs with the new inactive persistence path.
- [ ] Identify all old event-level retry ownership call sites that v0.11.0 must replace.
- [ ] Add a learning note about changing a state model in two increments.
- **Verify:** no documentation claims new per-delivery processing is active yet.

## Closure

- [ ] Lint, build, race-gated tests, migration tests, PostgreSQL integration, and API tests pass.
- [ ] `PROGRESS.md` records the dual-model compatibility boundary.
- [ ] Move this file to `done/`; promote v0.11.0 to `active/`.
